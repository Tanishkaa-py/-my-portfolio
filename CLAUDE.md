# CLAUDE.md

Guidance for Claude Code when working on this portfolio.

## What this is

A single-page personal portfolio for Tanishka Jain (data scientist, AI engineer, full-stack developer). Audience: recruiters and hiring managers, many of them non-technical. It must stay simple to understand and use, feel premium, and show only real work.

## Hard rules

- **Never invent content.** Every project, metric, date, award and certification must come from Tanishka's CV, LinkedIn, GitHub, or her direct instruction. If something is missing, ask; don't fill it in.
- **Plain English first.** Each project card leads with one sentence a non-technical person can follow. Technical detail lives in the pop-up.
- **No framework or build step** unless Tanishka asks to migrate. Keep it deployable as static files plus the serverless functions in `api/` (`chat.js`, `contact.js`).
- **Performance and accessibility:** respect `prefers-reduced-motion`, keep keyboard focus visible, keep the particle canvas paused when the tab is hidden, test at 390px wide.

## Design system

- Concept: "Darkroom". The one photo starts black and white and develops into colour under the cursor (tap on touch screens).
- One continuous space: each section has `data-theme="dark|light|accent"` and `main.js` sets the same attribute on `<html>` when that section crosses the middle of the screen. Dark: hero, tools strip, Knock Knock (#work). Light: about, story, recognition. Accent (deep blue): contact only.
- Sections have no backgrounds of their own. Components use the theme tokens (`--bg`, `--fg`, `--fg-2`, `--surface`, `--border`, `--link`…), which take their values from the raw palette under each `html[data-theme]` and fade over 0.8s.
- The particle sphere is one fixed canvas behind the whole page; its position per section is the `SCENES` table in `main.js`, its colours are the `--dot*` tokens.
- Tokens are at the top of `css/style.css`. Fonts: Bricolage Grotesque (display), Geist (body), Geist Mono (labels).
- Accent: `--accent` (blue, on paper) and `--glow` (periwinkle, on dark). Gold `--gold` is only for awards. `--safe-red` / `--safe-green` are only for the door safelights.

## Where things live

- Content data: `js/main.js` arrays `P` (projects: `area` is the one door it sits behind, `img` is a real screenshot in `assets/projects/` shown in a browser frame (falls back to the `art` illustration), `live` shows "Visit site" only when it's a real URL, `code` is `[label, url]` pairs, no `overview` means no pop-up), `AREAS` inside the doors block (door name, description, tool chips), and `C` (certifications: optional `verify` URL shows a "Verify ↗" link).
- Knock Knock (#work, the doors section): four door buttons, all closed on load; each opens one room of expanding project cards, and clicking the open door closes it. Built from `AREAS` + `P` in main.js. `window.openDoor(area)` opens a room for a guided tour.
- Timeline: `#storyList` in `index.html`.
- Hiring call to action: the "Open to … roles" pill in the top bar is a link to `#contact` (there is no Hire me button).
- "Ask Tanishka's AI": `js/assistant.js` (panel) talks to `api/chat.js` (Vercel function, AI SDK + Gemini, key in `GEMINI_API_KEY` env var only). Its knowledge is `data/profile.md`: built ONLY from site content, so **update it whenever projects, experience, awards or contact details change**. Tools in `api/_lib/tools.js`, rules in `api/_lib/prompt.js`, retrieval in `api/_lib/profile.js`, rate limit in `api/_lib/ratelimit.js` (in-memory; Upstash notes inside). The panel uses `data-lenis-prevent`. Test locally with `vercel dev`.
- Contact form + AI workflow: `js/contact.js` (form, inline validation, Turnstile only when the server returns a site key, the live diagram) posts to `api/contact.js` (validation, honeypot, Turnstile, 3 per visitor per hour), which runs `api/_lib/workflow.js`: Gemini sorts the message (`{category, company, role, urgency, summary, isSpam}`, message treated as data), spam stops, Nodemailer + Gmail notifies Tanishka (Reply-To the visitor; sent "Unsorted" if the AI step fails), then a short reply to the visitor (only when not spam): Gemini writes 2-4 sentences as Tanishka, `checkReply` blocks links, @, numbers, prices, dates, promises, their name and their words, and anything that fails (or a slow/failed Gemini, 5 s) falls back to the category template. No database. 20-second budget. Env: `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` (required in production), plus the Gemini vars. The diagram shows only steps the server returned. The assistant's `leaveMessage` only prepares a message; the visitor presses Send in the chat, which uses the same endpoint and a mini diagram (`window.contactFlow`). Gemini setup shared in `api/_lib/gemini.js`.
- Guided tour: `js/tour.js` (engine and widget) reads `data/tour-lines.json` (clips, single source of truth); audio is `assets/tour/{id}.mp3`, generated by `npm run tour:audio` (`scripts/generate-tour-audio.mjs`, keys in `.env.local` or `.env`, never committed). The tour must keep working with no audio files. Its highlight is a soft page dim around the target (never a box), and hero clips have no highlight (`"ring": false`). Its last clip (08, which rings `#contactBox` and keeps `.contact-links` clear) offers "Get in touch", which calls `window.focusContactForm()` (contact.js), and "Or ask my AI anything", which calls `window.openAssistant()` (assistant.js).
- Deployment: the live domain is `tanishkajain.vercel.app` (Vercel). It's set in `index.html` (canonical, og:url, og:image, twitter:image), `sitemap.xml` and `robots.txt`; change all of them together if the domain changes. Favicon: `assets/favicon.svg` and `assets/apple-touch-icon.png`.
- Each interaction is a self-contained IIFE block in `main.js` with a comment header.
